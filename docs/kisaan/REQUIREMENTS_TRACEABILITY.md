# KISAAN — Requirements Traceability Matrix

> Status: Draft v0.2 · Last updated: 2026-11-14 · Owner: KISAAN product & architecture · Source of truth index: [README](README.md)

This matrix links every requirement ID defined in the KISAAN documentation to its priority, owning document, owning module, data model, API, screens, KISAAN AI tools, tests and roadmap phase. It was **regenerated mechanically** from the v0.2 documents. Nothing was invented to fill a gap: where a link is not stated in the documents it is shown as an area-level link (`area: …`) or as **GAP**.

> **v0.2 changes:** rebuilt from scratch for Master Prompt v2. Old v0.1 prefixes `GRP`, `MEM`, `STR`, `CPN` are now `GROUP`, `MEMBER`, `STORE`, `COUPON`. The v0.1 "AI agents" area and the `ai-gateway` provenance tag are gone (one KISAAN AI, D-101/D-102). Test IDs follow `KIS-TEST-<DOMAIN>-NNN` (001–099 in TESTING_STRATEGY, 101+ in the domain docs). The v0.1 matrix is in [_archive/v0.1/REQUIREMENTS_TRACEABILITY.md](_archive/v0.1/REQUIREMENTS_TRACEABILITY.md).

## 1. How this matrix was built

- **Definition** = a table row whose first cell is the ID (`| KIS-X-NNN | … |`), or a bold inline definition in [MARKETPLACE_ARCHITECTURE](MARKETPLACE_ARCHITECTURE.md) §13.1. When an ID is defined in more than one doc (the PRD restates domain requirements), the **canonical owner** per the v0.2 reconciliation rules wins and is shown in *Owning doc §*:

| Prefixes | Canonical owner |
|---|---|
| `COUPON`, `MEMBER` | COUPON_AND_MEMBERSHIP |
| `OPSAPI` | OPSAPI_INTEGRATION |
| `REQ` | PRD §7.0 |
| `NFR` | PRD §7.1 |
| `PRC` | PRICING_ENGINE |
| `CMP`, `PRIV`, `SEC` | SECURITY_AND_COMPLIANCE |
| `INV`, `STORE` | SELLER_STORE_AND_INVENTORY |
| `AI`, `APR`, `VOX`, `WA` | SINGLE_AI_ARCHITECTURE |
| `BULK`, `GROUP`, `WHL` | WHOLESALE_AND_GROUP_BUYING |
| all other prefixes | [PRD](PRD.md) (or the only defining doc) |

- **Links** are taken from the documents' own cross-references, including ranges such as `KIS-GROUP-017…026` and lists such as `KIS-MEMBER-015/016`:
  - *Data*: tables in [DATABASE_SCHEMA](DATABASE_SCHEMA.md) whose heading, body or parent section cites the ID; otherwise `area: DB §x` (the schema section for that domain).
  - *API*: endpoint rows in [API_SPECIFICATION](API_SPECIFICATION.md) that cite the ID, shown as `METHOD path [TAG]` with `…` = `/api/v2/kisaan`. Tags: **NEW-KISAAN** (KISAAN plugin endpoint = the dynamic API created through OpsAPI's supported plugin mechanism), **EXISTING-OPSAPI**, **KISAAN-APP** (Next.js route handler), **TO-BE-VERIFIED**. Otherwise the API section that cites the ID, otherwise `area: API §x`.
  - *UI*: `SCR-*` screens in [UX_UI_SPECIFICATION](UX_UI_SPECIFICATION.md) on a line that cites the ID; otherwise `area:` = the screen range for that domain (UX rarely cites IDs).
  - *AI tools*: exact names from the [SINGLE_AI_ARCHITECTURE](SINGLE_AI_ARCHITECTURE.md) §8 catalogue (113 tools) that appear on a line citing the ID in any doc; otherwise `area:` = the tool category. `n/a` = no tool by design (security, compliance, NFR, admin).
  - *Tests*: `KIS-TEST-*` rows (TESTING_STRATEGY and the domain docs' 101+ tests) and `E2E-*` scenarios that cite the ID; otherwise `area: TESTING §x` (the domain suite). Only the first five are shown, with `+n` for the rest.
  - *Owner module*: the backend/runtime module that owns the domain in [SYSTEM_ARCHITECTURE](SYSTEM_ARCHITECTURE.md) §5.1 (module map). Named people/teams are not yet assigned (see §3, item 2).
  - *Phase*: the roadmap placement of the domain ([DEVELOPMENT_ROADMAP](DEVELOPMENT_ROADMAP.md) §3–§4) for MVP rows; `Post-MVP (P2)` and `Future (unphased)` otherwise.
- *Priority / class*: the scope cell of the defining row (MVP / P2 / Future). `KIS-CMP` rows carry the SECURITY_AND_COMPLIANCE classification instead (LEGAL REQ / RECOMMENDATION / ASSUMPTION, with `[LEGAL REVIEW]` / `[TAX REVIEW]` flags). `KIS-OPSAPI` rows have no scope column; they are Phase 0/1 foundation work and shown as `MVP (foundation)`.
- **Re-run** the generator after any change to IDs; the checks in §4 must stay at zero.
